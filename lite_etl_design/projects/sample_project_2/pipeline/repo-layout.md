# Repo layout - Northwind Commerce (DEMO)

> Phase 4 deliverable. The tree the project ships in, and what lives where.
> Derived from `design/10-platform-and-deployment.md` ("mono-repo `northwind-data/`")
> and the Phase 3 `build/repo/` scaffold.

- **Project:** Northwind Commerce - Unified Retail Analytics Harness
- **Date / version:** 2026-09-09 / v1.0
- **Repo model:** **mono-repo** - `dbt/`, `infra/`, `dagster/`, `extractors/` and
  the engines in one repo, one dbt project (split to project-per-domain only if
  build time exceeds the 35-min budget - `10` assumption). - because `10`
- **Host:** GitHub - org `northwind`, repo `northwind/northwind-data`
- **Default branch:** `main`

## Tree

```
northwind-data/
  extractors/                  # Phase 3 - 6 source modules + common/ framework
    common/                    #   config, state, secrets, landing, manifest, base, http, dbt_runner
    config/<src>.yml           #   per-source extract config (objects, lookback, page_size)
  recon/                       # Phase 3 - tag:recon compare + report + gate (PASS/FAIL)
  publish/                     # Phase 3 - gold/gold_pii transaction + UC catalog register
  lineage/                     # Phase 3 - run manifest + dbt manifest + OpenLineage emit
  obs/                         # Phase 3 - metrics + structured logging hooks
  dbt/                         # Phase 3 - staging / intermediate / marts / snapshots / seeds / macros / tests
    profiles/profiles.yml      #   targets: ci (duckdb), dev, stg, prd (databricks) - CI-injected
  northwind_dagster/           # Phase 4 - the Dagster code location ("the dagster/ dir" in the design).
                              #   Package is NOT named `dagster` so it never shadows the library.
    definitions.py             #   Definitions(assets, asset_checks, schedules, sensors, resources)
    partitions.py              #   daily business-date partitions (UTC)
    resources.py               #   databricks / s3 / secrets / dbt / alert resources - refs only
    assets/ingest.py           #   6 <src>_ingest assets -> bronze
    assets/transform.py        #   dbt project loaded via @dbt_assets (curated_build)
    assets/publish.py          #   publish + catalog_register + advance_watermarks + emit_metrics
    checks/reconcile.py        #   blocking asset check on the curated_build gold assets
    schedules.py sensors.py backfill.py
    deployment.yaml            #   Dagster Cloud code-location / OSS workspace descriptor
  infra/                       # Phase 4 - Terraform
    bootstrap/                 #   state bucket + DynamoDB lock table (no backend block)
    modules/{warehouse,storage,orchestrator,ga4,ci,observability}/
    envs/{dev,stg,prd}/        #   backend.tf  main.tf  <env>.tfvars
  .github/workflows/           # Phase 4 - pr.yml  main.yml  promote.yml  drift.yml
  tests/                       # unit (Phase 3) + fixtures + golden; integration/e2e added in Phase 5
  config/                      # non-secret config - defaults.yml + dev/stg/prd/ci.yml + <env>.generated.yml (from TF)
  docs/                        # dbt docs build output, runbook (Phase 5), ADRs (copied from design/)
  .pre-commit-config.yaml  CODEOWNERS  Makefile  pyproject.toml  README.md
```

## Generated vs authored

| Generated (do not hand-edit) | Authored |
|------------------------------|----------|
| `dbt/target/`, `dbt/dbt_packages/`, the `dbt docs` site | everything else |
| `config/<env>.generated.yml` (written by `terraform output`) | `config/defaults.yml`, `config/<env>.yml` |
| `.terraform/`, `*.tfstate*` (remote, never committed) | `*.tf`, `*.tfvars` |
| release notes (from merged PR titles) | `CHANGELOG` headers |
| `uv.lock` (regenerated by `uv`) | `pyproject.toml` |

## Promotion into the real repo

The Phase 3 `build/repo/` scaffold **plus** the Phase 4 additions above is the
seed. Phase 4 approach **(a)**: push `build/repo/` as the initial commit of a new
empty `northwind/northwind-data`.

- **First commit:** `chore: seed northwind-data from lite-etl-design phases 1-4`
  on branch `main`.
- **Then:** enable branch protection (`git-workflow.md`), create GitHub
  Environments `dev` / `stg` / `prd`, register the OIDC role (once `infra/ci` is
  applied - see `iac-plan.md` apply order).
- `build/repo/` stays the harness artefact of record; the live repo diverges from
  the first real PR onward.
